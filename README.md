# Вина для подборки — приложение к ДЗ-3

Streamlit-приложение использует сохранённый пайплайн `StandardScaler → LogisticRegression`.
Хорошим считается вино с исходной экспертной оценкой не ниже 7 из 10.
Обучение выполняется в ноутбуке, приложение модель не переобучает.

## Быстрый запуск

Проверено на **Python 3.12.14**. Используйте Python **3.12** и версии из `requirements.txt`.
Особенно важно совпадение версии scikit-learn с версией сохранённой модели — **1.8.0**.

Откройте терминал в этой папке `wine_app`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

На Windows виртуальное окружение активируется так:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откройте локальный адрес, который выведет Streamlit (обычно `http://localhost:8501`).
Также приложение можно запустить из корня проекта:

```bash
python -m streamlit run wine_app/app.py
```

Все пути к данным строятся от `Path(__file__).resolve().parent`, поэтому текущая
папка терминала не влияет на поиск модели и CSV.

## Вкладки

1. **Одно вино.** 11 числовых параметров и переключатель «красное / белое».
   Минимумы, максимумы и медианы взяты из `test.csv`, как разрешено условием.
   Это только настройки формы: они не участвуют в обучении модели.
2. **Модельные метрики.** Матрица ошибок, precision, recall, F1, accuracy,
   ROC/PR-кривые с точкой текущего порога. PR-AUC считается как average precision.
3. **Пакетное предсказание.** Загрузка CSV, прогноз по строкам, скачивание результата.
   При отсутствующих признаках, пустом файле, пропусках, нечисловых значениях и
   некорректном `is_red` выводится понятное сообщение об ошибке.
4. **Что выучила модель.** Отсортированные коэффициенты после масштабирования,
   признаки с наибольшими положительными и отрицательными коэффициентами.

Порог в боковой панели общий для всех вкладок. Его исходное значение читается
из `config.json` без предварительного округления. Кнопка возвращает исходный порог.

## Формат входного CSV

Обязательны следующие названия столбцов; их порядок может быть любым:

```text
fixed_acidity,volatile_acidity,citric_acid,residual_sugar,chlorides,free_sulfur_dioxide,total_sulfur_dioxide,density,pH,sulphates,alcohol,is_red
```

Числа записываются с десятичной точкой. `is_red` равен 0 для белого и 1 для красного вина.
`target` не нужен. Дополнительные столбцы сохраняются в выгрузке, но модель их не использует.
Результат содержит `probability_good`, `prediction` (0/1) и `decision`.

## Почему выбраны эта модель и порог

В исходном датасете 6 497 строк. До разбиения удалены 1 177 точных дубликатов.
Остались 5 320 уникальных строк; train — 3 724, test — 1 596.
Внутренняя validation составляет 25% от train. Во всех разбиениях используется
стратификация и `random_state=42`. Масштабирование обучается только на соответствующем train.

По validation выбран порог **0.23635860938278663**, максимизирующий precision
при recall не ниже 0.7. Validation precision = **0.4261**, recall = **0.7045**.
После этого пайплайн переобучен на всём train, а выбранный порог оставлен неизменным.

| Метрика финальной модели на test | Значение |
|---|---:|
| Accuracy | 0.7600 |
| Precision | 0.4213 |
| Recall | 0.7063 |
| F1 | 0.5277 |
| ROC-AUC | 0.8209 |
| PR-AUC / average precision | 0.4848 |

Матрица ошибок: TN = 999, FP = 294, FN = 89, TP = 214.
Модель находит 214 из 303 хороших вин; в подборке всего 508 вин.
Полнота 70.6% не означает, что 70.6% рекомендаций хороши: доля хороших среди
рекомендованных здесь равна precision = 42.1%.

Слайдер на test служит демонстрацией компромисса. Новый рабочий порог нельзя
выбирать по этой тестовой таблице: настройка должна выполняться по validation.
Вероятность является оценкой модели, а коэффициенты отражают условные статистические
связи, не причинное влияние признаков.

## Кэширование: ответ на задание 4.5

**`st.cache_resource` для модели.** Десериализованный пайплайн — ресурс: один и тот
же объект переиспользуется между перезапусками скрипта и сессиями. В приложении он
не изменяется. Это избавляет от повторного чтения `model.joblib` при движении ползунка.
Вызывать `fit` для такого общего объекта внутри приложения нельзя.

**`st.cache_data` для таблиц и массивов.** CSV и вероятности — данные, которые можно
сериализовать. Streamlit возвращает вызывающему коду копию кэшированного результата,
чтобы изменения данных одной сессии не затронули другую. Порог не входит в аргументы
`test_proba`, потому что вероятности от него не зависят. Аргумент `_model` начинается
с подчёркивания, поэтому объект модели не хэшируется. Версия файла модели отдельно
включена в ключ кэша, чтобы замена модели не оставляла старые вероятности.

**Без декоратора у `joblib.load`** каждый перезапуск `app.py` заново читал бы модель
с диска, тратил время и создавал новый объект. Если убрать кэш у `test_proba`, каждое
движение ползунка также заново запускало бы `predict_proba` для всего test, хотя
достаточно сравнить готовые вероятности с новым порогом.

## Публикация в Streamlit Community Cloud — задание 4.6

**Статус:** комплект подготовлен и проверен локально через Streamlit AppTest.
Публикация ещё не выполнена: для этого требуется вход в аккаунт Streamlit и доступ
к GitHub-репозиторию. Рабочая публичная ссылка не заявляется.

Самый простой способ публикации — отдельный репозиторий с содержимым этой папки
`wine_app` в корне:

1. Создайте GitHub-репозиторий, например `wine-quality-hw3`.
2. Загрузите в корень `app.py`, `model.joblib`, `config.json`, `test.csv`,
   `requirements.txt`, `README.md` и при необходимости `example_wines.csv`.
   Все файлы модели и данных уже включены; запускать обучение на сервере не нужно.
3. В [Streamlit Community Cloud](https://share.streamlit.io/) выберите **Create app**,
   затем **Yup, I have an app**.
4. Выберите созданный репозиторий, нужную ветку и главный файл **`app.py`**.
5. В **Advanced settings** выберите **Python 3.12** и запустите публикацию.
6. Дождитесь загрузки приложения, проверьте четыре вкладки и добавьте полученную
   ссылку `https://…streamlit.app` в последнюю ячейку ноутбука перед сдачей.

Если загружаете в GitHub весь проект, путь главного файла будет **`wine_app/app.py`**.
Файл зависимостей приложения лежит рядом с ним.

Версии приложения зафиксированы: в частности, scikit-learn 1.8.0 должен совпадать
с версией, при которой сохранён `model.joblib`.
